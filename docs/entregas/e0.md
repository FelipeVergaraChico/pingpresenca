# E0 — Base executável: entrega e evidências

Data: 10/09/2026 · Versão da aplicação: `0.1.0-e0` · Estado: **concluída no escopo E0**.

**Revisão posterior:** a [revisão E0/E1](revisao-e0-e1.md) corroborou a fundação e registrou uma lacuna de prontidão com schema desatualizado e pendências da E1. Os sete achados foram [corrigidos e revalidados](correcoes-e0-e1.md); o restante deste documento preserva a avaliação histórica.

Não representa conclusão do MVP. Este relatório preserva o estado histórico ao encerrar a E0, quando a próxima entrega era a E1. **Estado atualizado:** a [E1 — Preparar uma aula real](e1.md) foi concluída e validada; a próxima entrega é a E2. As pendências originais abaixo devem ser lidas junto dessa atualização e da nota ao final.

## Estado encontrado

Existiam os cinco documentos de planejamento, diretórios `frontend/` e `backend/` vazios e skills locais. Não existiam aplicação, manifests npm, migrations, Compose ou testes. O diretório `.git` apresentado pelo ambiente não foi reconhecido como repositório Git; nenhum histórico Git foi inicializado ou alterado.

## Implementado

- Workspace npm com React/TypeScript/Zustand e API Node.js/TypeScript/Fastify.
- Configuração validada, nome/fuso persistidos e utilitários de conversão temporal explícita. Relógio PostgreSQL para eventos e validade de sessão.
- Primeira migration SQL versionada, transacional, com checksum e trava de concorrência.
- Bootstrap com segredo de instalação, lock transacional, unicidade de owner no banco e marcador de conclusão durável.
- Conta/perfil/papéis separados, senha scrypt com salt, sessões opacas revogáveis e apenas hash de token no banco.
- Login/logout e consulta administrativa protegida como fundação de autenticação/autorização; nenhum CRUD acadêmico antecipado.
- Auditoria transacional do bootstrap e acesso, com dados mínimos, sem credenciais/segredos. Trigger impede reescrita pela operação normal da aplicação.
- Interface de bootstrap, login e conta conectada; configuração obtida da API; Zustand somente para estado visual efêmero.
- Compose de referência, imagens frontend/backend, PostgreSQL persistente, `.env.example`, guia local e licença AGPL-3.0-only.

As escolhas estão na [ADR 0001](../adr/0001-base-e0.md). Os requisitos acadêmicos originais não foram simplificados ou removidos.

## Problemas encontrados e resolvidos

- Sandbox bloqueou DNS npm, socket Docker e IPC do runner tsx. Operações necessárias foram reexecutadas com acesso apropriado; os testes não foram marcados como aprovados nessas primeiras falhas.
- Vitest 3 apresentava aviso moderado. A atualização direta encontrou erro interno do npm 10 (`edgesOut`); o lockfile foi gerado com npm 11 temporário, sem instalação global, e depois validado por `npm ci` com npm 10. Versão final: Vitest 4.1.11.
- Primeira tentativa Compose coincidiu com a resolução do lockfile e falhou no build do serviço de migration. Após correção do lockfile, o ensaio completo foi repetido e aprovado.
- O encerramento padrão do Playwright deixou seu PostgreSQL temporário ativo. Foi configurado encerramento gracioso por SIGTERM e o recurso identificado foi removido. A repetição para validar a limpeza foi interrompida: o serviço Docker Desktop foi encerrado pelo `systemd-oomd`, conforme registro do systemd, e deixou de responder. A tentativa de iniciá-lo pela CLI não restabeleceu o daemon. A limpeza graciosa ainda precisa ser comprovada em nova execução; o script agora também informa o alvo exato quando não consegue removê-lo.
- Após essa interrupção, `npm run typecheck`, `npm test` (8 backend + 3 frontend), `npm run build` e a verificação sintática do script de navegador foram repetidos e aprovados. Não se atribui a falha de infraestrutura à aplicação nem se considera essa última execução do navegador aprovada.

## Pendências e limites conhecidos

- Nenhuma funcionalidade da E1 foi iniciada: convites, CRUD de contas/papéis, disciplina, turma, matrícula, local e aula estão pendentes.
- Recuperação de owner via comando, gestão de contas, SMTP, chamadas, frequência, piloto real, testes de carga e atualização/backup/restauração completos seguem seus marcos.
- Não há avaliação humana com leitor de tela, certificado público ou validação de turma real nesta entrega.
- Limites por IP de login/bootstrap e confiança do proxy são iniciais; precisam ser ajustados antes do acesso compartilhado de turmas. Não existe promessa de capacidade medida na E0.
- Não foi criado `.env` com credenciais pessoais nem owner na instalação do usuário. Inicialização real exige preencher `.env` e fazer bootstrap; **não precisa de seed**.
- Os recursos dos ensaios de integração e Compose e o container da primeira execução de navegador foram descartados. A interrupção do Docker impediu confirmar/remover o container sintético da última repetição: `pingpresenca-e0-browser-79eec3767396`. Quando o daemon estiver disponível, limpar exclusivamente esse alvo com `docker rm -f -v pingpresenca-e0-browser-79eec3767396` (remove apenas banco sintético descartável) e repetir `PLAYWRIGHT_CHANNEL=chrome npm run test:browser`, verificando a ausência de containers com prefixo `pingpresenca-e0-browser-` ao terminar. Imagens/cache de build podem permanecer; nenhum recurso de outro projeto foi removido.
